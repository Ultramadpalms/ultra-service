# Ultra Service — редактируемый прототип

Восстановлен по опубликованным версиям сайта владельца. Структура главной адаптирована с учётом ruszeekr.ru; тексты, контакты и изображения конкурента не используются. Текущая версия предназначена для обсуждения структуры. Финальный стиль и публикация на домене — следующие этапы.

## Файлы

- `dist/index.html` — вся структура, тексты, цены и контакты. Содержимое доступно без JavaScript.
- `dist/styles.css` — оформление и адаптация под экраны. Цвета и размеры задаются переменными в начале файла.
- `dist/script.js` — мобильное меню. Раскрытие симптомов использует стандартный HTML details.
- `dist/assets/` — изображения с исходного сайта. Они являются иллюстрациями, а не фотографиями подтверждённых работ.
- `.openai/hosting.json` — указан каталог для статического размещения, проект хостинга не зарегистрирован.

Зависимостей и обязательной сборки нет. Для простого просмотра можно открыть `dist/index.html`, для полной проверки использовать локальный HTTP-сервер. На хостинг загружается содержимое `dist`, а не родительская папка.

## Структура

1. Шапка: навигация, телефон, режим работы.
2. Первый экран: специализация, запись, начальная цена диагностики.
3. Каталог из шести направлений.
4. Цены: известная цена ZDS, порядок оценки остальных работ.
5. Симптомы: четыре раскрываемых сценария.
6. Электроника и ВВБ — подробные блоки.
7. ПО, привязка, удалённая диагностика, HV, восстановление после ДТП.
8. О сервисе.
9. Этапы работ.
10. Контакты и маршрут.

Отзывы, блог и отдельные страницы услуг из примера пока не добавлены: для них нужны собственные материалы и подтверждение объёма. В исходном сайте раздел «Кейсы» фактически показывал рендеры. Они не представлены как реальные выполненные работы.

## Размещение на домене

1. Выбрать домен и хостинг статических сайтов. Сервер приложений и база данных для текущей версии не нужны.
2. Загрузить содержимое `dist` в корень сайта, проверить главную, все изображения и меню.
3. Указать домен в панели хостинга; затем внести именно выданные им DNS-записи у регистратора. Не менять записи почты.
4. Включить HTTPS и выбрать основной адрес: с www или без. Настроить перенаправление второго варианта.
5. Добавить canonical с окончательным адресом, sitemap.xml и robots.txt; снять meta robots noindex,nofollow только у готового публичного сайта. Пока прототип закрыт от индексации этой меткой.
6. Изображение для превью сохранено в `dist/assets/og.png`; текущий og:image сохранён как в исходнике. При переносе заменить его на абсолютный URL этого файла на новом домене. Добавить og:url с адресом главной.
7. При необходимости настроить /premium/ на главную на стороне хостинга. Перенаправление со старого github.io потребует доступа владельца к старому репозиторию.
8. Проверить телефонные ссылки, WhatsApp, маршрут, работу на телефоне и HTTPS. Затем можно подключить аналитику и инструменты поисковых систем.

Форма отправки заявки сейчас отсутствует: запись идёт через телефон и WhatsApp, как на исходном сайте. Если потребуется форма, нужно отдельно выбрать способ получения заявок, обработать ошибки отправки и подготовить соответствующие документы.

Пароли, токены и секретные настройки в проекте отсутствуют.
